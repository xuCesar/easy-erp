# Factory ERP Lite UI Visual System V1

日期：2026-05-20
适用阶段：Phase 1.7 UI 品牌升级
适用范围：`apps/admin`、`apps/miniapp`

## 1. 视觉定位

Factory ERP Lite 的 Phase 1.7 视觉方向是“数据驾驶舱”。

目标不是做高噪音大屏，而是让工厂管理人员和一线员工快速理解考勤状态、异常风险、审批动作和月报结果。界面应体现可靠、清晰、工业现场友好和可持续扩展。

关键词：

- 数据清晰。
- 工业可信。
- 状态可判读。
- 操作低负担。
- 双端一致。

## 4. Admin 设计规则

Admin 采用 Tailwind-first + shadcn/ui。

布局：

- 顶层 shell 使用驾驶舱式工作台布局。
- 顶部展示产品、当前阶段、登录态和关键操作。
- 左侧导航保留七个 section，视觉上强化当前模块。
- 内容区使用卡片栅格，不使用复杂多级菜单。

表格：

- 默认中等密度。
- 表头使用弱背景区分。
- 状态字段使用 badge。
- 空态必须说明下一步动作。
- 不在 Phase 1.7 引入复杂虚拟列表或高级表格引擎。

表单：

- 继续支持当前 inline create flow。
- 输入框、按钮、错误反馈使用 shadcn 风格组件。
- 错误信息就近展示，不吞掉请求错误。

数据驾驶舱元素：

- 月报、考勤结果和审批模块可以使用小型 KPI 卡片。
- KPI 只基于现有数据计算，不新增接口字段。
- 不引入图表库；如需图表，进入后续任务单独评估。

## 5. 小程序设计规则

小程序采用 `weapp-tailwindcss` + 自有 Taro 组件。

页面结构：

- `PageShell` 负责背景、标题、副标题和安全留白。
- `Card` 负责内容分组。
- `Field` 负责输入项。
- `PrimaryButton` 负责主行动。
- `StatusText` 负责反馈状态。

移动端原则：

- 主按钮点击区域不小于 88rpx 高度。
- 表单字段标签必须清晰，不依赖 placeholder 作为唯一说明。
- 打卡页优先展示今日状态、班次、考勤组和主行动按钮。
- 考勤记录页优先展示日期、主状态、上下班时间和锁定状态。
- 请假和补卡页必须保留提交中、成功和失败反馈。

## 6. 依赖边界

Admin 允许新增：

- Tailwind CSS 相关依赖。
- shadcn/ui 所需依赖。
- 少量无样式基础依赖，仅限 shadcn 组件必需项。

Miniapp 允许新增：

- Tailwind CSS 相关依赖。
- `weapp-tailwindcss`。

禁止：

- 为 Admin 引入 Ant Design、Ant Design Pro 或大型后台框架。
- 为小程序引入额外 UI 组件库。
- 把 UI 组件抽到 `packages/shared-types`。
- 因 UI 重构修改 API、数据库 schema 或 shared-types。

## 7. 验收样例

Admin：

- 登录前后视觉状态明确。
- 工厂范围筛选区不遮挡主内容。
- 七个 section 在桌面和窄屏下均可操作。
- 表格空态、数据态、只读态和可管理态可区分。

小程序：

- 登录、打卡、考勤记录、请假、补卡、个人页视觉一致。
- 真机预览下按钮点击面积充足。
- 状态反馈不依赖颜色单独表达。
- API 失败时有清晰可见反馈。
